# Locked decisions (MVP)

Decisions from SPEC §17, locked for implementation.

| # | Decision | Choice |
|---|----------|--------|
| 1 | **Payment gating** | **Option A:** Only "approved paid" Entries can submit picks. |
| 2 | **Autopick tie-break** | Earliest kick-off in that Gameweek, then alphabetical by team name. |
| 3 | **Fixture source** | Manual entry for MVP; automated import later. |
| 4 | **Split winners (≤5 wipe-out)** | Record as "Split winners" in UI and in WhatsApp message; list winning Entry IDs. |
| 5 | **Wipeout threshold** (2026-09-22) | Configurable per season via `rules.wipeout.splitPrizeAtOrBelowEntries`, default 5. Was previously hardcoded in `settleGameweek` despite the config field already existing — fixed to actually read it. |
| 6 | **Club branding vs. platform theme** (2026-09-22) | The app's own dark "Matchday Energy" identity is fixed and never swapped per club. A club's own branding (logo/colour/name) is confined to isolated badge elements (a bordered card, an accent stripe, one CTA button) rather than tinting whole pages or popups — chosen specifically so an organiser's bad or clashing colour choice can't break page readability. |
| 7 | **Transactional email provider** (2026-09-22) | Resend, sending from `lastman@1zero9.com` (root-domain address — a subdomain would need its own separate DKIM/SPF verification, which the Resend plan in use doesn't support alongside the existing verified domain). |
| 8 | **Admin stays outside the theme rollout** (2026-09-22) | Matchday Energy applies to player-facing and public pages only. Admin pages share the root layout (single shared header/nav/dock, no route groups yet), so a true edge-to-edge per-route background swap would need a larger layout restructure — deferred; each themed page currently renders as a large dark panel within the existing content column rather than bleeding to the viewport edge. |
| 9 | **Competition setup codes replace the shared organiser access code** (2026-09-23) | Removed the single `ORGANISER_ACCESS_CODE` env var that gated all self-registration forever. Every competition now needs its own one-time code, generated (and only ever visible) in `/platform` by a platform admin, redeemed once at the point `/admin/setup` actually creates the competition. Also found and fixed a real gap this surfaced: no account held `PLATFORM_ADMIN` in production, so `/platform` was unreachable by anyone, including the founder. |
| 10 | **Fixture source is now automated** (2026-09-23) | Supersedes #3. Real Premier League fixtures and results come from football-data.org (free tier: 10 calls/min, delayed rather than live scores — fine, since only final results are needed). Manual score entry on `/admin/results` still exists as the fallback for leagues without an automated source, or if the API is down. |
| 11 | **When the pre-loaded schedule runs out with the game still live, extend by default** (2026-09-23) | The next real matchweek is pulled in automatically and play continues without asking first — "Last Man Standing" is expected to actually produce one. A `RoundAnnouncement` still surfaces to the organiser (dashboard + email) so it's never silent, and gives them a one-click override to settle early and split the pot instead if they'd rather not keep extending. Deliberately not gated behind the wipeout split threshold — that's a different rule for a different situation (everyone eliminated together in one round). |
| 12 | **Buy-back window: first two rounds only** (2026-09-23) | Applies to both the organiser-recorded buy-back and the new self-service request — an entry can only buy back in if it was eliminated in gameweek 1 or 2, regardless of `rules.buyBack.maxPerEntry`. Chosen so buy-back covers an early bad break, not a standing way to re-enter deep into the season. |
| 13 | **Preview deployments get their own database** (2026-09-25) | `PRISMA_DATABASE_URL`/`POSTGRES_URL`/`DATABASE_URL` were originally scoped to both `production` and `preview`, so any preview build shared production's real data. Provisioned a dedicated Prisma Postgres instance for `preview` only (same schema, applied via migration), and rescoped the original instance to `production` only. |
